# Demo landing pages

Static end pages for synthetic phishing samples used in email security product demos.

Site: https://williammirelesss.github.io/sublime-demo-landing-pages/

Every page is fabricated and inert:

- static HTML with inline CSS only, generated by `build_site.py`
- no forms, inputs, buttons, scripts, iframes, external assets, trackers, cookies or analytics
- a visible "Sublime Security Demo Asset" banner on every page
- a strict `Content-Security-Policy` meta tag (`default-src 'none'`, `form-action 'none'`)
- `noindex, nofollow` meta on every page and a `robots.txt` that disallows everything
- dense product-style file chrome sized so a roughly 700 by 520 link-preview viewport is
  filled with useful file UI rather than a small card over blank space

All names, companies, invoice numbers and phone numbers are fictional.

## Layout

```
build_site.py                    generator, the only source of page content
routes.json                      every published path and its expected marker (generated)
check_site.py                    pre-publish gate and live health check, stdlib only
docs/                            the published site (generated, served by GitHub Pages)
.github/workflows/link-health.yml
```

## Change a page

```bash
python3 build_site.py                 # regenerate docs/ and routes.json
python3 check_site.py --local docs    # must exit 0 before pushing
git add -A && git commit && git push
```

Never hand-edit `docs/`. CI rebuilds it and fails if the committed copy differs.

## Health check

`link-health` runs daily at 06:17 UTC, after every Pages build, on every push to
`main`, and on demand. It fetches every route over HTTPS and fails if any route:

- does not end on HTTP 200, or redirects off this site
- is blank, or loses its banner or route marker
- gains a form, input, script, external reference, or login / CAPTCHA wording
- loses its CSP or noindex meta tag

Run it locally against the live site:

```bash
python3 check_site.py --base https://williammirelesss.github.io/sublime-demo-landing-pages/
```

## Opaque hop paths

GitHub Pages cannot send HTTP 301 or 302 responses. Stable opaque paths under
`/s/<code>/` are HTTP 200 pages with an immediate HTML meta refresh
(`content="0; url=..."`) and a visible fallback link. Each hop page renders the
same dense file UI as its final page, so clients that do not follow the refresh
still capture a complete preview. QR, Teams, each calendar target, and DocuSign
have unique codes. The Drive- and Figma-style samples use direct file paths.

`/go/viewer/` remains live only for already-ingested historical copies.

## Limits

- Public content stays public. `noindex` and `robots.txt` reduce discovery, they do
  not make anything private. `robots.txt` is only honoured at a host root, so on a
  project site the per-page `noindex` meta is the control that matters.
- GitHub Pages has no SLA. A GitHub outage takes every link down at once.
- GitHub disables scheduled workflows in public repositories after 60 days without
  repository activity. Re-enable `link-health` from the Actions tab if that happens.
- Response headers cannot be customised on GitHub Pages, so CSP is delivered as a
  meta tag rather than a header.

## Recovery

1. Check the latest `link-health` run for the failing route and reason.
2. If Pages itself is down, check https://www.githubstatus.com and wait.
3. If Pages was disabled, re-enable it: Settings, Pages, source `main` branch,
   folder `/docs`.
4. If a page broke, fix it in `build_site.py`, rebuild, run the local gate, push.
